A green CodeRabbit check can mean “not reviewed”.On PRs #60, #61 and #62 the CodeRabbit status reported “Review rate limited” and passed anyway. The v0.8.0 rotation inversion — which changes production behaviour on every operator-managed cluster — therefore carries no external review, only its own tests and a hand-checked mechanism. Worth reading the badge, not just its colour, before treating a merge as reviewed. The converse bit too, on PR0b: it sat BLOCKED for 3.5 hours with every check green, because a git filter-branch --msg-filter rewrite had stripped the commits' GPG signatures and the repo's required_signatures ruleset refused them. Nothing in the checks list says so — gh pr merge reports the block without the reason, while PUT /pulls/N/merge names the offending rule outright. Green checks are not the merge gate, and the tool that tells you it is blocked is not the tool that tells you why. And a third form, found on PR3: an empty commit never triggers the CodeRabbit app, so a required CodeRabbit check sits pending forever — nothing is failing, nothing is coming, and only an explicit @coderabbitai review comment releases it. Taken together the three are one lesson in three costumes: a green badge can mean not reviewed, green checks can coexist with an unmergeable PR, and a pending check can mean nothing was ever asked. Read what a signal is actually evidence of, not what its colour suggests.
