WireMesh · Build Progress

Zero-trust network fabric — cycle-by-cycle build tracker

Open-source (Apache-2.0), self-hosted, cloud-agnostic L3/L4 network fabric in Rust: WireGuard data plane, default-deny eBPF policy, one gateway per segment, no agents on workloads. The engineering design ships as four plan cycles; this page tracks what's done, in flight, and next.

Resolved · v0.9.0
A gateway scaled to 0 reported itself healthy.Backlog 2b shipped: replicas is now omitted from the apply body rather than force-applied as Some(1), so kubectl scale --replicas=0 finally sticks — the key is omitted, not set to null, because under server-side apply only omission releases ownership. The reason it had been held back was the misreport it would ship with: gateway readiness is roster-based — apply_gateway computes enrolled from the controller’s roster and never reads Deployment status — so a gateway scaled to 0 kept reporting Enrolled: True off a still-active roster row, the CR claiming a dead data plane was live. Decision + fix pending
The in-step blocker is cleared — the timer is still off, and now off by default everywhere.Updated v0.10.0/v0.10.1: an absent WIREMESH_ROTATION_INTERVAL used to resolve to a 30-day timer in every shipped artifact except the operator path — the .deb/.rpm ship the variable commented out, the container image sets no ENV, a source build sets nothing. It now means no timer, so the live fabric's off is one instance of the shipped default rather than a local override, and nobody arms a known-broken mechanism by installing a package. A second correction shipped with it: earlier releases documented fabricctl rotation as the supported manual path and that was never true — there is no fabricctl rotate subcommand. On-demand rotation is the Admin RotateKey RPC only, which binds loopback-only by design, so triggering one means a hand-rolled gRPC call from the controller host (BACKLOG item 33). The rest of this entry stands. The controller rotates every active gateway on one 30-day timer, so the fabric rotates in step — a scenario nothing had ever tested. The done bar written 2026-08-05 for exactly that found six bugs, all fixed across v0.7.1–v0.7.5, two of them fatal on their own: a gateway’s active key permanently left its base port at the first cutover so the second rotation could not complete, and a stranded retiring row excluded that gateway from the timer permanently — rotation was self-disabling after one round, silently. The seventh bug was the in-step case itself, and v0.9.1 fixed it: the bar is green and the #[ignore] is gone (key_rotation 7/7, nothing ignored). What remains is one code defect and one call. The defect is the rotation wedge in the entry below (backlog 9, still open): on_directive is honoured only from Idle, and handle_rotate advances the phase before the fallible mint/bring-up, so one failed rotation parks that gateway and it silently ignores every directive after it until the process restarts — survivable while directives are manual and watched, load-bearing the moment a 30-day timer issues them unattended. The call is that WIREMESH_ROTATION_INTERVAL=off is still set on the live px controller, and re-enabling it is also an operational decision about a running multi-site fabric — a first in-step round would cut over every gateway at once, and it has never been exercised anywhere but netns. Until someone makes that call, keys do not rotate on a schedule: a real posture cost, not a neutral pause. Note also that the setting alone was never the whole picture — v0.8.0 found an absent variable makes the controller default to 30 days, so operator-managed clusters had rotation ARMED regardless of the px controller; the operator now emits off explicitly. (A second suspected blocker, a boringtun socket leak leaving the reserved port double-bound, was observed with ss and downgraded: the leak is real and larger than predicted, but newest-bound wins deterministically on Linux and the leaked socket could not be made to win even warm and CPU-pinned.)
Known gap
The rotation wedge — three ways in.on_directive is honoured only from Idle, and the only path back is a completed retire. Anything parking the phase off-Idle makes the gateway silently ignore every later directive and never scrub the old private key. Most reachable: handle_rotate advances the phase and then does fallible work, so one lost name race is enough. A bare reset is not the fix — it must unwind partial setup or it trades one wedge for another. Latent only because the timer is off — and since v0.10.0 it is off by default, which removes the fabric-wide exposure but not the defect. This is BACKLOG item 9 and Phase B's B2; it is the thing that gates arming the timer anywhere.
